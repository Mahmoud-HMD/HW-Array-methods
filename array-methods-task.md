# Задача: «Лаборатория методов массива»

Тема: мутирующие и немутирующие методы массива в React.

Один экран: список персонажей с API и панель кнопок. **Каждая кнопка — один метод.** Плюс встроенная проверка на мутации: кнопка «Сбросить» обязана всегда возвращать исходные 20 персонажей. Если где-то случайно мутировал state, сброс сломается, и это сразу будет видно.

## Шпаргалка

| Мутируют (меняют исходный массив) | Не мутируют (возвращают новый) |
|---|---|
| `push`, `pop` | `map`, `filter` |
| `splice` | `slice` |
| `sort`, `reverse` | `concat` |
| | `join` (возвращает строку) |

Запоминалка: `splice` мутирует, `slice` — нет. Разница в одну букву, поведение противоположное.

## Экран

```
 Лаборатория методов        Исходных: 20 · Сейчас: 17   [Сбросить]

 НЕ МУТИРУЮТ
 (map: КАПСОМ) (filter: только Alive) (slice: первые 5)
 (concat: +гости) (join: имена строкой)

 МУТИРУЮТ (только на копии!)

 │ [фото]  Rick Sanchez         │

```

## Что должна делать каждая кнопка

| # | Кнопка | Метод | Что делает |
|---|---|---|---|
| 1 | `map`: КАПСОМ | `map` | все имена в списке становятся заглавными |
| 2 | `filter`: только Alive | `filter` | в списке остаются только живые |
| 3 | `slice`: первые 5 | `slice` | в списке остаются первые 5 персонажей |
| 4 | `concat`: +гости | `concat` | в конец добавляются оба гостя |
| 5 | `join`: имена строкой | `join` | над списком появляется строка `Rick Sanchez, Morty Smith, ...` |
| 6 | `push`: добавить гостя | `push` | в конец добавляется первый гость |
| 7 | `pop`: убрать последнего | `pop` | удаляется последний персонаж |
| 8 | `splice`: вставить в середину | `splice` | второй гость вставляется на 3-ю позицию |
| 9 | `sort`: по имени | `sort` | список сортируется по имени A→Z |
| 10 | `reverse`: наоборот | `reverse` | порядок списка переворачивается |

## Правила

1. **Исходный список нельзя портить.** Загруженные 20 персонажей лежат в отдельном state `original` и не меняются **никогда**. Кнопка «Сбросить» возвращает список к ним.
2. **Мутирующие методы использовать обязательно**, но только на **копии**:

```jsx
const copy = [...characters];

copy.pop();
setCharacters(copy);
```

Писать `characters.pop()` нельзя.

3. **В шапке видно `Исходных: 20 · Сейчас: N`.** Если после нажатия любой кнопки число «Исходных» изменилось, значит где-то произошла мутация. Это баг.
4. `map`, `filter`, `slice`, `concat` возвращают новый массив, их результат сразу идёт в `setCharacters`.
5. `join` ничего не меняет в списке: результат кладётся в отдельный state и показывается над списком.

---

## Главная проверка на мутацию

1. Нажми `sort`, потом «Сбросить».
2. В шапке должно снова быть `Исходных: 20 · Сейчас: 20`, а список — в исходном порядке (Rick, Morty, Summer…).

Если после сброса порядок остался отсортированным — значит `sort` вызвали на массиве из state, а `original` и `characters` указывали **на один и тот же массив**. Это самая важная ошибка в задаче: найди её и разберись, почему так вышло.

## Подсказки

- `copy.pop()` возвращает **удалённый элемент**, а `copy.push(x)` — **новую длину**. В `setCharacters` должен уходить сам массив `copy`, а не результат метода.
- `splice(2, 0, гость)` значит: на позиции 2 удалить 0 элементов и вставить гостя.
- Для сортировки строк нужна функция сравнения: `(a, b) => a.name.localeCompare(b.name)`.
- `map` создаёт новый массив, но объекты внутри остаются теми же. Чтобы поменять имя, нужен новый объект: `{ ...character, name: ... }`.
- `join(', ')` работает со строками, поэтому сначала `map` по именам, потом `join`.

## Бонус ⭐

1. **Журнал операций.** Под кнопками строка вида `map · filter · sort` с историей нажатий. Добавлять в неё только немутирующим способом.
2. **`toSorted` и `toReversed`.** Новые немутирующие версии `sort` и `reverse`. Перепиши кнопки 9 и 10 на них и проверь, работают ли они в твоём браузере.
3. **Оживить первого.** Кнопка меняет `status` первого персонажа на `Alive`, не мутируя объект. Подсказка: `map` + spread.
